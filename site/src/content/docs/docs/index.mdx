meteo by Azohra publishes soaring forecasts for a flying community. The
forecast engine builds versioned JSON documents for the launches you
catalogue; the TypeScript packages validate those documents and draw the
charts. Any layer can run on infrastructure its operator controls.

## Where to begin

Every capability's section in the sidebar opens with its own first steps
and carries its install command. The three doors most readers want: the
operator's path starts at
[Configure launches](/docs/forecast/configure-launches/), the TypeScript
reader's at
[Render a first Meteogram](/docs/briefing/render-first-meteogram/), and the
station owner's at
[Station getting started](/docs/station/getting-started/). The rest of
this page is the map of how those layers fit.

## The responsibility boundary

| Layer | Responsibility | Output or policy |
| --- | --- | --- |
| [`@azohra/meteo.grib`](/docs/grib/) and [`@azohra/meteo.j2k`](/docs/j2k/), the decoders | Provider bytes beneath the engine: GRIB2 sections, grids, and packing, and the JPEG 2000 codestreams inside ECCC messages | Decoded grids, gated bit-for-bit against ecCodes |
| [`@azohra/meteo.forecast`](/docs/forecast/), the forecast engine | Provider input, model-dependent sampling, and quantities that require unpublished inputs or cross-run authority | Published profile values |
| Versioned JSON | Portable model, site, time, semantics, source-field, and derived-value documents | The data boundary between publisher and consumer — [Compatibility](/docs/compatibility/) carries the one rule for reading it |
| [`@azohra/meteo.briefing`](/docs/briefing/) npm package | Contract validation, pure document derivations, scene construction, hit-testing, and reference SVG | Reusable analysis and presentation primitives |
| [`@azohra/meteo.station`](/docs/station/) npm package | Live weather-station reading, derivation, and display: client, server, React, and custom-element bindings | The [station capability](/docs/station/) |
| [`@azohra/meteo.core`](/docs/core/), the shared foundation | Units, angle and wind-vector math with one sign convention platform-wide, zod primitives, and the upstream-failure vocabulary | The [shared physical vocabulary](/docs/core/) the briefing and station packages build on |
| The [operator](/docs/glossary/#operator) | Location selection, schedule, hosting, retention, presentation, access, verification, and safety language | A complete publication for their audience |

The platform ships [the engine, not an
instance](/docs/forecast/#engine-not-instance); an operator composes it
into a pipeline of their own.

## Who owns each value

The forecast engine owns the **stored derivations** — values that cannot be
derived from the published profile alone, including
its boundary-layer, thermal-velocity, cloud-base, and usable-lift series. The briefing
package owns the **pure derivations** — functions of the published document — and the reference
renderer. Presentation
parameters, such as timezone, windows, palette, overlays, and sink-rate choices exposed by the
renderer, belong to the consumer.

The parameterized `usableLiftTopM` is the explicit exception spanning that boundary. The
implementation is the package's pure function; the engine imports it and stores its 1.0 m/s
evaluation as the authoritative published value, so a consumer projecting another sink rate runs
the same code that produced the stored series.

The model catalogue is authoritative for declared capabilities and provider semantics. The
[model-capabilities guide](/docs/forecast/model-capabilities/) explains how consumers render those
declarations.

The chart at the end of the pipeline is the **Meteogram**: surface forcing
aligned with the atmosphere above one model grid cell.
[Reading a Meteogram](/docs/briefing/reading-a-meteogram/) explains every
mark on it, the [glossary](/docs/glossary/) carries the platform's other
terms of art, and the [logbook](/logbook/) records how the derivations
and visual conventions were established. Where the platform came from, and
the projects it descends from, is [the about page](/about/).
