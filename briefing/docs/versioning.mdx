`@azohra/meteo.briefing` (currently <code>{BRIEFING_PACKAGE_VERSION}</code>)
versions the read side: contract guards, derivations, analysis,
comparison, transport, history, scene graph, SVG renderer, tokens, and
the scene-derived key. The package version is independent of every
document's `schemaVersion` —
[Compatibility](/docs/compatibility/) carries the document families and
the one rule for reading them.

The package follows semantic-versioning intent. While it remains below
1.0:

- patch releases in one minor line are backwards-compatible corrections;
- a minor release may change a public TypeScript or JavaScript API and
  describes the change in the changelog and the TypeScript docs; and
- a deprecation names the replacement and the release boundary at which
  the old export may disappear.

Pin an npm range appropriate to your tolerance, validate all external
documents, and test deterministic and ensemble examples. Switch on the
scalar value shape and declared capabilities, never a hard-coded model
name.

## Finding vocabularies

Three typed kind sets version independently of the package and of each
other:

| Constant | Current value | Authority | What it versions |
| --- | ---: | --- | --- |
| `ANALYZE_VOCABULARY_VERSION` | <code>{ANALYZE_VOCABULARY_VERSION}</code> | `briefing/src/analyze/vocabulary.ts` | The [single-profile finding kinds](/docs/briefing/analyze/) |
| `COMPARE_VOCABULARY_VERSION` | <code>{COMPARE_VOCABULARY_VERSION}</code> | `briefing/src/compare.ts` | The [cross-model comparison kinds](/docs/briefing/compare/) |
| `RUN_COMPARISON_VOCABULARY_VERSION` | <code>{RUN_COMPARISON_VOCABULARY_VERSION}</code> | `briefing/src/history/compare-runs.ts` | The [run-comparison kinds](/docs/briefing/history/) |

The current release publishes site-forecast documents at
`schemaVersion: 2`, and its analysis and comparison envelopes carry the
profile contract's `Mps` suffix grammar (`wstarMinMps`,
`peakThermalVelocityMps`, `meanWindMps`, `directionFloorMps`, and their
siblings). Envelopes serialized under earlier vocabularies keep their old
bare-`Ms` field names, and the runtime version check catches the skew.

## Release tags are snapshot boundaries

Treat each package release tag as an API and SVG snapshot boundary while
validating each document's independent `schemaVersion`. The
[scene guide](/docs/briefing/scene/) defines the current presentation
options and scene fields; the [SVG guide](/docs/briefing/svg/) defines
rendering, tokens, and the scene-derived key. The
[package changelog](https://github.com/azohra/meteo/blob/main/briefing/CHANGELOG.md)
records release comparisons.
